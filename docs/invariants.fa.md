# Invariantها: قاعده‌های متعلق به پروژه

invariant یک بررسیِ **متعلق به پروژه** است که قبل از قبول هر package اجرا می‌شود و Kargah از محتوایش چیزی نمی‌داند. مثال‌ها در [project-dependencies.fa.md](project-dependencies.fa.md): «target تست باید ایمیج را قبل از run بسازد»، «`print` و `logging.getLogger` در کد API ممنوع».

## چرا جدا از `check.sh`
- Kargah باید بتواند بگوید **کدام قاعده** شکست خورد و آن را در `log.jsonl` بشمارد (برای `/retro`).
- installer باید بتواند فهرستشان را نشان بدهد («با چشم باز»).
- `check.sh` تست‌های کار است؛ invariant قانون خانه است. ارزان‌تر است و اول اجرا می‌شود.

## قرارداد (پیشنهاد، برای بحث)

- **جا:** `.kargah/invariants/`، هر قاعده یک فایل اجرایی با shebang، به هر زبان. ترتیب اجرا: نام فایل (`10-no-print.py`، `20-images-before-run.sh`).
- **ورودی:** cwd = ریشه‌ی ریپو. متغیرهای محیطی: `KARGAH_ROOT`، `KARGAH_LAYER` (`api|ui|core` یا خالی)، `KARGAH_BASE` (sha شروع package)، `KARGAH_PATHS` (فایل‌های تغییرکرده، هر خط یکی).
- **خروجی:** exit code `0` = برقرار، `77` = «به این package مربوط نیست» (skip)، هر عدد دیگر = شکست. آخرین ≤۵ خط stdout/stderr به agent و مالک نشان داده می‌شود.
- **قیدها:** فقط‌خواندنی (فایلی را تغییر ندهد، `--fix` ندارد)، بدون تعامل، timeout از `config` (پیش‌فرض ۱۲۰ ثانیه؛ timeout = شکست).
- **اجرا:** اول، قبل از `check.sh`. اولین شکست متوقف می‌کند. شکست مثل شکست check شمرده می‌شود (دوباره یک دور، بار دوم توقف و پرسیدن)، ولی در لاگ با نام فایل ثبت می‌شود: `invariant_fails` و فهرست نام‌ها.
- **امنیت:** invariant کد پروژه است و با مجوز کاربر اجرا می‌شود. `init` هیچ invariant‌ای را خودکار اجرا نمی‌کند؛ فقط فهرست می‌کند و اجازه می‌گیرد.

## مثال: قاعده‌ی ایمیج قبل از اجرا (از v1)
قاعده‌ی تست حذف‌شده، به شکل invariant: برای هر target فهرست‌شده در فایل (`targets.txt` کنار آن) خروجی `make -n <target>` را بگیرد و اگر `run` قبل از `build` آمد exit 1 بدهد. پروژه‌ی بدون Makefile با exit 77 رد می‌شود.

## سؤال‌های باز
1. `ALLOWED: <دلیل>` (مثل `# repo-rules: allow` پروژه): invariant می‌تواند استثنا را چاپ کند تا به reviewer برسد؟ (پیشنهاد: بله، خط‌هایی با پیشوند `ALLOWED:` در brief reviewer می‌آید.)
2. invariant ها per-layer یا سراسری؟ (فعلاً سراسری، با exit 77.)
3. آیا Kargah باید قالب چند invariant رایج را بدهد (no-print، no-secrets، ایمیج)؟ (پیشنهاد: نه؛ فقط مثال در `docs/`.)
